Teniendo este avance, la planificación ágil (Scrum) se actualiza y agiliza de la siguiente manera:

**FASE 1: El "Mise en Place" técnico (Sprint 0 - Configuración inicial)**
Dado que el esquema de base de datos ya está finalizado, esta fase debe completarse en los próximos 2 días.

* **Gestión del Proyecto (Beltrán):** Configurar el tablero Kanban en GitHub Projects. Crear las columnas: Backlog, To Do, In Progress, Review y Done.

* **Esqueletos de código (Diego Zafra y Daniel Roanes):** Inicializar el proyecto Spring Boot (configurando el `application.properties` o `.yml` con la cadena de conexión a la BBDD) y el proyecto de Flutter Web.

**FASE 2: Creación del Product Backlog**
Beltrán (Product Owner) fragmentará los requisitos del documento en tareas medibles (Historias de Usuario) dentro de GitHub Projects.

* Ejemplos Backend: "Mapear entidades JPA del esquema speedkitchen", "Implementar controlador y servicio para registro de usuarios".
* Ejemplos Frontend: "Maquetar vista de Login", "Configurar cliente HTTP (Dio/http) en Flutter".

**FASE 3: El Sprint 1 (Fundamentos y Autenticación)**
El primer ciclo de desarrollo (2 semanas) omitirá el motor multijugador para centrarse exclusivamente en la infraestructura base y la gestión de usuarios.

* **Zafra (Backend):** Trasladar las 12 tablas del script SQL a entidades JPA en Spring Boot. Configurar Spring Security y exponer los endpoints REST para registro y autenticación (generación de tokens JWT).
* **Daniel (Frontend):** Desarrollar las pantallas de Login y Registro en Flutter Web y ejecutar las peticiones POST contra los endpoints del backend para validar la comunicación cliente-servidor.
* **Torre (Full-Stack/BBDD):** Dar soporte a Zafra en el mapeo de relaciones complejas en Hibernate, especialmente las claves compuestas de las tablas intermedias (`recetas_ingredientes`, `amigos`).
* **Beltrán (Scrum Master):** Supervisar el flujo del tablero Kanban, auditar que las tareas se mueven correctamente, resolver cuellos de botella de integración y asegurar que los *Pull Requests* se revisan antes de fusionarse a la rama `main`.

**Operativa del equipo**

1. **Planificación (Día 1 del Sprint):** Reunión de 45 minutos. Selección y asignación de tareas del Backlog que comprometen entregar al final de la iteración.
2. **Sincronización (Daily Stand-up):** Reunión de 10-15 minutos. Cada integrante expone exclusivamente tres puntos: qué hizo ayer, qué hará hoy y qué bloqueos técnicos tiene. No se utiliza para debatir código.
3. **Revisión (Último día del Sprint):** Despliegue en local de la integración entre frontend, backend y base de datos para probar el flujo de las tareas completadas.

El siguiente paso técnico crítico para el equipo es determinar si la base de datos PostgreSQL de desarrollo se alojará en un servicio cloud (como Supabase, Render o AWS RDS) para que tanto Zafra como Roanes puedan consumirla simultáneamente, o si trabajarán con bases de datos locales independientes.
